# GD32F350 option bytes and protection

## Two different axes

The UI reports two independent things:

1. **Security protection (SPC)** — a hardware setting in the option bytes that
   locks debug access.
2. **ROM DFU bootloader access** — whether the ROM bootloader (in system
   memory, outside main flash) will serve flash.

On the GD32F350 the ROM bootloader still reads flash while SPC is *low*, so a
device can be "Protected: Low" and "ROM DFU bootloader access: Accessible" at
the same time. That is not a contradiction.

Reading flash never erases it. The mass erase happens only when protection is
*removed* (`OB_SPC` changed to `0xA5`), which erases the whole main flash,
including the flash bootloader.

## Option byte layout at 0x1FFFF800

Each value byte is followed by its complement:

| Offset | Field | Notes |
|--------|-------|-------|
| `0x00` / `0x01` | `SPC` / `SPC_N` | security protection |
| `0x02` / `0x03` | `USER` / `USER_N` | user option bits |
| `0x04` / `0x05` | `DATA0` / `DATA0_N` | user data |
| `0x06` / `0x07` | `DATA1` / `DATA1_N` | user data |
| `0x08` / `0x09` | `WP0` / `WP0_N` | write protection low |
| `0x0A` / `0x0B` | `WP1` / `WP1_N` | write protection high |
| `0x0C`–`0x0F` | reserved | `0xFF` |

## SPC values

| SPC | Meaning |
|-----|---------|
| `0xA5` | No security protection |
| `0xBB` | Low security protection (any value other than `0xA5`/`0xCC`) |
| `0xCC` | High security protection (irreversible) |

The tool accepts `0xA5` and `0xBB`, and refuses `0xCC` (and any inconsistent
value/complement pair) before touching flash.

## USER bits used by the dialog

- bit 0: independent watchdog
- bit 1: reset on stop mode
- bit 2: reset on standby mode

Bits 3 and 7 are reserved and preserved on write. Bits 4–6 (BOOT1, VDDA
monitor, SRAM parity) are preserved from the current value.

## Changing SPC

- Setting low protection (`0xBB`) restricts debug access and requires typed
  confirmation.
- Removing protection (`0xA5`) triggers a full mass erase, including the flash
  bootloader, and requires typed confirmation (`UNLOCK`).
